# BTGC Group — marketing website

Static multi-page site (HTML5 + Tailwind CSS v4 + GSAP 3.13 + Lenis). 21 pages, no framework.

## Structure
```
index.html about.html services.html projects.html quality-hse.html certifications.html contact.html 404.html
services/   mechanical · electrical · phe-fire · elv · civil · interior-fitout · maintenance .html
projects/   6 case studies
assets/js/  motion.js (Lenis+GSAP, preloader, reveals, pins, cursor, page transitions)
            main.js (navbar, menu + focus trap, Flip filter, lightbox, cert modal, form validation)
assets/img/ placeholder SVGs (descriptive names) + hero skyline JPG from the company profile
src/input.css   Tailwind v4 CSS-first config (@import "tailwindcss"; @theme { … })
dist/output.css built CSS
tools/      data.mjs (ALL copy/content) · partials.mjs (header/footer/icons) · build-pages.mjs · placeholders.mjs
```

## Build
```bash
npm install --include=dev      # note: NODE_ENV=production would skip dev deps
npm run build                  # regenerates every .html + dist/output.css
npm run css:watch              # CSS only, while styling
npm run serve                  # or: python -m http.server 4173
```
CSS command: `npx @tailwindcss/cli -i ./src/input.css -o ./dist/output.css --minify`

Header/footer are generated into every page from one template, so they stay identical. Edit content in `tools/data.mjs`, then `npm run build`. (You can also edit the HTML directly if you stop using the generator.)

### Quick dev preview without building CSS
In each page `<head>`, replace the `dist/output.css` link with the browser build (**development only**):
```html
<script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script>
<style type="text/tailwindcss">@import "tailwindcss"; @theme { /* paste @theme from src/input.css */ }</style>
```
Custom component CSS in `src/input.css` must be pasted into that `<style>` block too, so the compiled CSS is the easier route.

## Home hero (services slider)
- Slide data: `heroSlides` in `tools/data.mjs` (title, meta line, sub-text, icon, image stem, link) → `npm run build`.
- Images: each slide uses `assets/img/hero/<stem>.avif` (served to screens wider than 1280px) with `<stem>.webp|.jpg` (1920w) and `<stem>-1280.webp|.jpg` as fallbacks. Current mapping: `1`–`6` + `interior` (4 and 5 are the same photo). To change a photo: replace the `.avif`, then run `npm run hero-images` to regenerate the fallbacks (uses `sharp`). Stems are set in `heroSlides` in `tools/data.mjs`.
- Behaviour: `assets/js/hero-slider.js` (loaded on `index.html` only, after `motion.js`). The slides follow the real scroll position — wheel, trackpad, scrollbar, keyboard and touch all work; scroll ~60px and the next slide appears, and when scrolling pauses the page glides to that slide. Styles: the "HOME HERO" block at the end of `src/input.css`.
- The section after the hero carries `id="after-hero"` (the target of "scroll down" / skip).

## Deploy
The site is fully static; publish the project root (HTML, `assets/`, `dist/`). `dist/output.css` is committed/generated by `npm run build`.

- **Netlify**: connect the repo — `netlify.toml` already sets the build command (`npm install --include=dev && npm run build`), publish dir `.`, security/cache headers and the 404 page. Or drag-and-drop the folder after running `npm run build` locally.
- **Vercel**: import the repo — `vercel.json` sets build command, output dir `.` and cache headers.
- **cPanel / shared hosting**: run `npm run build` locally, then upload everything except `node_modules/`, `tools/`, `src/` and `*.pdf` into `public_html/` (FTP or File Manager). Enable gzip/Brotli and long caching for `/assets/` in `.htaccess` if your host does not by default. Use `404.html` as the ErrorDocument.
- After deploy: set the real domain in `site.url` (`tools/data.mjs`), rebuild, and submit `sitemap.xml` in Google Search Console.

## Quality checks run
Lighthouse (mobile, simulated throttling, local server): Accessibility 100, Best Practices 100, SEO 100 on all tested pages; Performance ≈ 87–97 depending on page and run (higher on a CDN with compression). Automated checks also confirm: one `<h1>` per page, no skipped heading levels, alt text on every image, no horizontal overflow at 360 / 1024 / 1920 px, no console errors.
The first-visit preloader (≤1.6 s, once per session) is the main cost on LCP; set `sessionStorage` key `btgc-pre` or remove the preloader markup if you need a higher lab score.

## Motion & accessibility notes
- Content is visible without JS: hidden states only apply under `html.js`; a 6 s failsafe removes the gate if scripts never start.
- `prefers-reduced-motion`: no Lenis, pinning, parallax, SplitText, preloader or transitions — everything shows immediately.
- Preloader runs once per session (sessionStorage); page transitions are a navy/red slash wipe.
- Pinned horizontal projects + WBS timeline are desktop-only (≥1024px) via `gsap.matchMedia()`; stacked on mobile.
